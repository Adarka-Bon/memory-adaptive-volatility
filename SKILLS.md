## 2. Алгоритм сборки реферата (порядок важен)

```powershell
cd C:\Users\DASHA\AppData\Local\Temp\opencode
python apply_body.py     # 1. пересборка тела из body_text.py + body_text2.py
python finalize.py       # 2. Word COM: оглавление 1-2, обновление полей, PDF
```

`apply_body.py`:
1. Открывает `БондаренкоДД_Реферат.docx` (он же и источник, и результат — сборка идемпотентна).
2. Удаляет всё тело **между «Введением» и «Приложением А»** и вставляет заново содержимое
   `BODY + BODY2` (вместе с заголовком «Перечень сокращений», который ставится **перед** «Введением»).
3. Пересобирает **Приложение А** (20 слайдов по 6 на листе) и **Приложение Б** (скриншоты сайта + QR).
4. **Приложение В не трогает** — оно остаётся в исходном файле как есть.
5. Добавляет нумерацию страниц (поле `PAGE` в колонтитуле, снизу по центру, титул без номера).
6. Сохраняет в `БондаренкоДД_Реферат.docx`.

`finalize.py` (Word COM через pywin32):
1. `TablesOfContents.Item(1).UpperHeadingLevel = 1`, `LowerHeadingLevel = 2`, `toc.Update()` —
   **только так**: правка `instrText` через python-docx не приживается.
2. `doc.Fields.Update()`, `doc.Repaginate()`, `doc.Save()`, `doc.ExportAsFixedFormat(pdf, 17)`.

Правка содержания реферата = правка `body_text.py` / `body_text2.py`, затем шаги 1–2 выше.
**Не редактировать .docx вручную**: правки будут потеряны при следующей пересборке.

## 5. Переносимые навыки (по исследовательской части)

Блок «Навыки, приобретённые при выполнении работы» — содержание подготовлен отдельным
документом, в реферат пока **не вставлен**: основной текст уже 20 стр. при потолке 21,
вставка даст +1…2 стр. Если вставлять — только краткий вариант и с сокращением §1.6–1.8.

1. **Подготовка и анализ финансовых временных рядов** — доходности и реализованная волатильность,
   приведение котировок разных классов активов к единому виду, пропуски и выбросы, дневные и минутные данные.
2. **Оценка долгосрочной зависимости** — R/S, логарифмический периодограммный метод, тест Ло;
   выбор ширины окна, локальная сила памяти, границы применимости оценок.
3. **Диагностика нестационарности и режимов рынка** — CUSUM-тест, сравнение кризисных и спокойных
   периодов (тест Уэлча с бутстрэп-коррекцией), локализация моментов смены режима.
4. **Построение и проверка эконометрических моделей волатильности** — HAR-RV, walk-forward на
   расширяющемся окне, метрики MSE и QLIKE, ограничения статической параметризации памяти.
5. **Разработка и обучение нейросетевых моделей временных рядов** — Standard, ProbSparse,
   MultiFeature на PyTorch, контроль переобучения, сопоставление по качеству и устойчивости.
6. **Проектирование моделей с учётом изменчивости среды** — локальная оценка памяти как
   управляющий сигнал маски внимания, обоснование сравнением режимов работы модели.
7. **Оценка рыночного риска по прогнозу волатильности** — VaR и ES, тяжесть хвостов, бэктестинг,
   достаточность капитального резерва.
8. **Построение воспроизводимого исследовательского конвейера** — модульный код с конфигурацией
   экспериментов, фиксация результатов в CSV и графиках, ноутбук, воспроизводящий выводы.
9. **Прикладная интерпретация результатов** — перевод оценок в язык риск-менеджмента,
   отделение значимых закономерностей от лежащих в пределах шума.

## 6. Типовые грабли (проверено на практике)

1. **Кириллица в PowerShell-скриптах.** Файл `.ps1` без BOM читается как ANSI → путь ломается,
   скрипт не парсится. Любую работу с путями и кириллицей делать **из Python-скрипта**
   (`win32com`, `shutil`), а не из PowerShell.
2. **`python -c "…"` с кириллицей** в PowerShell ломает кодировку (cp1251). Только файлы-скрипты.
3. **Порядок вставки через `addprevious`.** Элемент вставляется непосредственно перед якорем,
   поэтому вставлять нужно **в прямом порядке** (заголовок → список), иначе блок перевернётся.
4. **Оглавление.** Уровни и номера страниц обновляются только через Word COM; после правок
   в `body_text*.py` обязательно запускать `finalize.py`.
5. **Идемпотентность.** `apply_body.py` читает и пишет один и тот же файл. Любой «хвост» между
   «Введением» и «Приложением А» нужно вычищать в самом скрипте (см. `_clean_before_intro()`),
   иначе старые блоки дублируются при пересборке.
6. **Копирование файлов.** `Copy-Item -LiteralPath` не раскрывает `*` — использовать `-Path`
   либо `shutil.copy2` (он же сохраняет время модификации).
7. **Файл, открытый в Word**, не перезаписывается — сохранять под новым именем.
8. **Скриншоты сайта**: Chrome headless `--screenshot`, предварительно отключить анимации
   (`.reveal{opacity:1!important;transform:none!important}`), иначе виден только первый экран.
9. **PDF** читать `pymupdf` (`fitz`), рендерить страницами; `pdftoppm` в системе нет.

## 7. Проверки перед сдачей

* **Требования кафедры** — таблица раздела 4 (страницы считаются по PDF, а не по абзацам).
* **Оригинальность** — сравнение 8-грамм с локальными корпусами (Vaswani 2017, Gatheral 2018,
  Nie 2023, собственные статьи). Сейчас: 0,00–0,29 %, совпадают только названия в списке литературы.
  Настоящий антиплагиат (Антиплагиат.ВУЗ) считает по вузовской базе — её видно только с вашим логином.
* **Оформление** — поля/шрифт/интервал читаются из `styles.xml` и `sectPr` самого .docx.
* **Ссылки на рисунки и таблицы** — каждая подпись должна иметь ссылку в тексте.
* **Самоповторы** — искать повторяющиеся 8-граммы внутри текста (должно быть ≤3–4, все терминологические).
